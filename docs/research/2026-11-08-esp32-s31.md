# ESP32-S31 能力与应用项目调研

调研日期：2026-11-08（Asia/Shanghai）。本轮将用户所说“ESPS31”按 ESP32-S31 理解；本地厂商工程 [sdkconfig](E:/ESP32-SERVICE/sdkconfig) 的目标也明确为 `esp32s31`、RISC-V。

本文补充[能力池](../CAPABILITY_POOL.md)。重点是可参考的用途、交互和底座机制，不以尺寸、板型或固件差异提前排除能力。没有编译、刷机、连接外设或实机验证。

## 1. 最值得关注的增量

相较于此前围绕 ESP32-S3 的项目，S31 相关资料带来几条更具体的参考路线：

1. **电脑外设**：USB 副屏、触摸输入、声卡、外接相机／麦克风／键盘等，不只有联网对话。
2. **音频角色**：经典蓝牙音乐、免提通话、媒体状态同步，以及 LE Audio／Auracast 共享收听。
3. **本地视觉与短指令**：先由小模型或固定语音命令触发动作，复杂问题再交给服务器。
4. **设备小应用**：用对话创建／修改 Lua 应用，设备负责运行、传感器和界面，模型服务可在外部。
5. **多节点与模块组合**：Matter 中枢／桥接、ESP-NOW 协作、可发现外设和主辅屏互动。
6. **低功耗后台**：让低功耗核执行简单采样或事件判断，再按需唤醒主核。

以上都是候选方向，不表示本机已经实现。芯片规格、官方演示、公开代码与完整产品分别标注；厂商工程、其他开发板和替代运行环境也分别对待。

### 2.1 视觉性能应按模型选择

参考项目展示了从快速小模型到秒级按需识别的不同档位，不宜统一称为“实时 AI”：

| 来源 | 模型与输入 | 作者／官方所列耗时 | 对功能选择的启发 |
| --- | --- | --- | --- |
| S31-01 | ESPDet-Pico 猫检测，224×224 | 推理约 89 ms | 可研究低频持续事件检测 |
| S31-03 | YOLO11n int8，320×320 | 作者记录两块开发板约 1.9～2.3 s | 更适合“拍一次、等结果”的交互 |
| S31-01 | YOLO11n，640×640 | 推理约 8.7 s | 复杂模型要有等待反馈，或改用服务器 |

不同输入、模型和测量范围不能直接横向当作统一跑分。本轮没有复测。通用语音理解、自由文本生成也不能由这些视觉小模型能力推定。

新增九个讨论项，其余优先补强现有条目，不为同一功能反复建编号。

| 能力池 ID | 候选用途 | 来源 |
| --- | --- | --- |
| U-09 | USB 连接电脑，作为麦克风、扬声器或带屏语音终端 | S31-07、S31-08 |
| U-10 | 侧边滑条、背部触摸、接近／触摸唤醒等非屏幕输入 | S31-12、S31-13 |
| U-11 | 与手机配对，承担蓝牙免提通话与屏幕通话控制 | S31-04 |
| S-08 | USB 桌面副屏、文档或选定窗口的静态镜像 | S31-07、S31-08；低频镜像是适合本项目的组合推导 |
| S-09 | 主辅屏分别呈现内容，或多块设备协同显示与互动 | S31-18、S31-15 |
| V-13 | 姿态关键点、手部区域事件与动作交互 | S31-01、S31-02；动作次数等应用仍需另做 |
| H-14 | Matter／Thread／Zigbee 接入、中枢和桥接角色 | S31-14；具体协议与角色分别选 |
| H-15 | 基于 ESP-NOW 等近场链路进行多设备协作 | S31-15；不默认替代全部 Wi-Fi／服务端功能 |
| F-05 | LE Audio／Auracast 一对多共享收听或广播 | S31-04、S31-06 |

补强已有条目：

- **S-06 动态小应用**：ESP-Claw 的 Agent 技能与 Lua 应用分别打包，可作为可扩展终端的重要参考。
- **V-04／05／10／11／12**：二维码／标记、对象与人脸、小模型、外部相机、手势均有 S31 明确入口。
- **V-09、K-08**：音视频与原音保存可参考留言机，但不改变统一聊天记录入口。
- **R-04、R-05**：USB 键盘／存储外设和复合设备，扩展原有编辑与传输路线。
- **F-04、T-12**：手机音乐／媒体信息、外部蓝牙输出和局域网对讲已有参考。
- **F-01／02／03**：模块化体感、环境输入、LED 与表情，可由独立节点或副屏完成。
- **U-02／05**：本地唤醒、固定命令、预设中文 TTS 与服务器自由问答可以分层组合。

## 6. 与本项目核心方向的联系

这些是设计推导，不是本轮确定的首期范围：

- **问答**：本地唤醒／固定命令负责快速交互，复杂问答由服务器处理，声音可按场景送到本机、电脑或蓝牙设备。
- **记录**：继续以聊天保存意图为主；图像和原音可作为关联材料，USB 可作为传输或电脑接入通道。
- **知识整理**：仍由服务端与 Obsidian 链路承接。S31 提供更丰富的输入、展示和执行方式，不据此把知识合并任务全部下放到设备。
- **扩展底座**：动态应用与外设目录值得优先纳入讨论，它们决定今后新增相机、卡片或设备动作时，是否都要修改整套主固件。

所有新增条目保持待选择。原始代码、框架或官方演示的适配工作后续自主完成；本轮没有作出技术栈替换或系统迁移决定。
